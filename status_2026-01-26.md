## ⚠️ PROBLEMAS IMPORTANTES

### 4. **URLs de servicios incorrectas para Docker**
**Archivo:** `.env` líneas 11-34

Los servicios usan `localhost` en lugar de los nombres de servicio Docker:

```dotenv
AUTH_SERVICE_URL=http://localhost:3002
USER_SERVICE_URL=http://localhost:3001
GAME_SERVICE_URL=http://localhost:3003
IMAGE_SERVICE_URL=http://localhost:3004
```

**Problema:** En Docker, los contenedores no pueden comunicarse via `localhost`. Deben usar los nombres de servicio: `auth`, `user`, `game`, `images`.

**Solución recomendada:** Crear un `.env.docker` separado:
```dotenv
AUTH_SERVICE_URL=http://auth:3002
USER_SERVICE_URL=http://user:3001
GAME_SERVICE_URL=http://game:3003
IMAGE_SERVICE_URL=http://images:3004
```

## 🔐 PROBLEMAS DE SEGURIDAD

### 8. **Token en URL para WebSockets**
**Archivo:** `packages/game/src/gateways/GameGateway.ts` líneas 27-35

Los tokens JWT se pasan por query string (`?token=...`). Esto puede quedar en logs de servidores.

**Mitigación actual:** `access_log off;` en nginx para la ruta WS.

**Mejora sugerida:** Considerar autenticación via primer mensaje WS o cookies httpOnly.

---

### 9. **Sin rate limiting**
No hay protección contra brute force en:
- Login (`/auth/login`)
- Registro (`/auth/register`)
- Rutas públicas

**Solución:** Implementar `@fastify/rate-limit` en gateway y auth.
